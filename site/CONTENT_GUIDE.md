# Writing docs pages

Site: Astro + Starlight in `site/`. Pages live in `src/content/docs/<section>/<slug>.md` (or `.mdx` when the page uses
components). URL: `/collections/<section>/<slug>/` (`/collections` is the base path of the GitHub Pages site).
The `api/` folder is generated by TypeDoc and `reference/compatibility-report.md` by `npm run test:diff:proof`: never edit them.

Source of truth: the library in `../src/**/*.ts` and its tests in `../tests/`. Never document behaviour you did not verify.

## Only as much as the reader needs

- Engineers using the library. Lead with what a thing is for, then code. Short sentences, plain English, no marketing,
  no "simply", no emoji.
- One idea per section. Cut background a reader of a collections library already knows (what a linked list is, what
  O(log n) means). Cut repetition between pages: say it once, link to it.
- Prefer one good example over three similar ones. A table beats a paragraph of method names.
- No diagrams. A short text tree or a table does the job.

## Frontmatter

```yaml
---
title: Maps                       # sidebar label and h1
description: One sentence, at most 160 characters, used for SEO and link previews.
sidebar:
  order: 4                        # position within the section
---
```

Do not repeat the title as a `#` heading; start the body with a paragraph. Use `##` and `###` only.

## Code blocks

Every ```` ```ts ```` block is a doctest (`npx jest tests/docs.test.ts`): it is compiled under strict mode and run against
`../src`, and each `console.log(x); // → expected` must print exactly `expected`.
- Import only from `'@ylcnfrht/collections'`.
- A block that cannot run (a signature, pseudo-code, code that is meant to fail) is fenced ```` ```ts nocheck ````.
- Shell: ```` ```sh ````. Plain output: ```` ```text ````. File titles: ```` ```ts title="cache.ts" ````.

## Components (only in `.mdx`)

```mdx
import { Tabs, TabItem, Aside, Badge, LinkCard, CardGrid } from '@astrojs/starlight/components';
import ClassInfo from '../../../components/ClassInfo.astro';
```

- Basic / Intermediate example pairs: `<Tabs syncKey="level">` with `<TabItem label="Basic">` and
  `<TabItem label="Intermediate">`. Leave a blank line before and after each code fence inside a TabItem, and keep the
  fence at column 0.
- Package managers: `<Tabs syncKey="pm">` with npm / pnpm / yarn / bun.
- `<ClassInfo name="ArrayList" />` directly under each class heading on the collection pages (source file, base
  class, and JDK verification numbers, read at build time).
- `<Aside type="tip|note|caution">` for a real gotcha, at most two per page.

## Links

Absolute, with the `/collections` base path and a trailing slash, never to the `.md` file: `/collections/collections/maps/` or
`/collections/concepts/equality/#writing-equals-and-hashcode`. API pages live under `/collections/api/...` (generated). The build
validates every internal link and anchor.

## Building

```sh
cd site && SKIP_TYPEDOC=1 SKIP_LINKS=1 ASTRO_OUT_DIR=<scratch>/dist npx astro build
```

While other sections are still being written, keep `SKIP_LINKS=1`; the full link check runs at the end.
